# Kling 4.0 — promotion admission and measurement

**DECISÃO APROVADA — fundador, 28/10/2026:** paid active subscribers receive up to three Kling 4 films/ads per UTC day, each up to 60 seconds, without credit debit during their 30-day window. New subscriptions must start by 30 November 2026 inclusive; existing subscribers count from launch. The shared fal promotion budget is US$100 per UTC day. Cap exhaustion returns normal credit pricing with an honest message. This document covers the new promotion core; it does not declare the engine pipeline published.

**FATO CONFIRMADO / IMPLEMENTADO:** `lib/kling4PaidPolicy.ts` defines `KLING4_PAID_LIVE` and `KLING4_PROMO_LIVE` as explicit environment opt-ins: only the literal `true` enables either switch. `false`, absent or malformed values disable it. `KLING4_PROMO_LAUNCH_AT` must be a valid UTC ISO timestamp with seconds, earlier than 1 December 2026. It has no invented default. Missing/future launch suppresses free admission and offer copy. Turning the paid switch off selects Kling 3 upstream; the promotion cannot independently enable Kling 4.

**FATO CONFIRMADO / IMPLEMENTADO:** `lib/kling4PromoServer.ts` derives the user from the authenticated route and revalidates the linked provider subscription at runtime. `has_paid`/`is_pro` never grant this promotion. Stripe requires a live `active` subscription, matching owner metadata/customer, a positive paid latest invoice and future paid period. PayPal requires `ACTIVE`, matching owner and mapped plan, a positive last payment and future next billing time. Dodo requires live mode, active matching-owner subscription plus the existing server-only live `payment_success` record with a positive amount. `trialing`, `past_due`, packs, administrative trial plans, unverified or missing provider data do not authorize free admission. Provider reads in tests are injected fixtures; no live provider was called.

**QUESTÃO PENDENTE / DESCONHECIDO:** Paddle has profile references but no implemented billing verification transport in this repository. A Paddle-only profile cannot prove active paid entitlement to this core and fails closed. Stripe's strict latest-invoice proof may also reject an active subscription whose latest invoice is zero despite a previous paid period. These cases require billing verification, not a `has_paid` bypass.

**FATO CONFIRMADO / IMPLEMENTADO — revisão, 29/10/2026:** legacy paid labels `creator` and `studio`, recognized by `lib/ads/access.ts:26` and `lib/plan.ts:62`, are accepted alongside canonical `basic`/`pro`. `normalizeKling4PaidPlan` compares the equivalent PayPal tier while the stored label remains in measurement and the RPC checks the exact current profile link. The label alone still grants nothing; active positive paid provider verification remains mandatory. Offline policy, provider and SQL tests cover both aliases and reject a mismatched/unpaid subscription.

**FATO CONFIRMADO / IMPLEMENTADO:** `reserveKling4Promo(admin,{userId,jobId,seconds,kind,falExtrasMilliUsd})` first reads an immutable prior decision, then verifies the subscription and invokes `reserve_kling4_promo`. Client status, plan, eligibility or cost cannot authorize a zero-credit generation. The RPC rechecks the current profile subscription link, provider verification freshness and window. A user-level enrollment freezes the first window; renewals, plan changes and later subscription IDs cannot reset an enrolled person's 30 days. The exact cutoff is subscription start `< 2026-12-01T00:00:00Z`; qualifying November subscriptions may continue into December until their own 30-day expiry.

**FATO CONFIRMADO / IMPLEMENTADO:** the migration generated with Supabase CLI is `supabase/migrations/20261029025654_kling4_paid_promo_daily_budget.sql`. It adds four new RLS-enabled service-only tables and security-invoker RPCs with empty search path. No trial table/function/module was changed. Lock order is request identity, person, person/day, then the global UTC-day row. Films and ads share the same three-use counter and US$100 ledger. Reservation and admission event commit together. Failed event insertion rolls back both. Neither uncertainty nor account/generation deletion replenishes a reserved allowance.

**FATO CONFIRMADO / IMPLEMENTADO:** integer milliUSD reservation is `seconds × 157 + falExtrasMilliUsd`, implementing the founder's US$0.157/s cost input. Extras are server-provided bounded fal expenses that must be reserved **before** those calls; allowed range is 0–10,000 milliUSD. The film/ad pipeline owns its exact bound, including stills, fal audio and possible fallback video. No later fallback may exceed that bound. Costs outside fal do not belong to this fal ledger. A failed/unavailable reserve does not grant free rendering; normal credit pricing applies upstream. Reservation consumption is attempted/accepted work, not a guarantee of three completed deliveries.

**FATO CONFIRMADO / IMPLEMENTADO:** a cap/quota decision is stored as credit-priced for that request identity. Replays return `duplicate:true` and the exact original decision even after UTC rollover, expiry or switch rollback; they never authorize another provider POST. The caller must resume the existing claim. `verifyKling4PromoReservation` permits shared settlement to recognize zero cost only from a matching free server ledger row, with kind/duration checks. A browser marker alone is insufficient.

**FATO CONFIRMADO / IMPLEMENTADO:** `kling4_promo_use_reserved` records admission and `recordKling4PaidUse` records `kling4_paid_engine_used` after the provider accepted its submission. Both are idempotent by user/request and blocked in the browser event sink. They contain person, plan, kind, seconds, subscription start, promotion expiry and dollar cost with `cost_basis=reserved_upper_bound`. They do not assert completed delivery or invoiced fal cost. The usage event is meaningful only after the pipeline calls the acceptance helper.

**SUGESTÃO / medição:** fix a launch cohort by UTC subscription start and exclude `lib/internalAccounts.ts` accounts. Count unique external subscribing people per week; sum reservation upper bounds and accepted-use upper bounds separately, then join completed film/ad delivery by the same generation/order ID. Divide cohort-attributed cost by new external subscribers in that same dated cohort; do not equate requests/events with people, or reserved cost with the fal invoice. Compare actual billing when available.

**FATO CONFIRMADO / IMPLEMENTADO:** `GET /api/kling4-paid/availability` is read-only and private/no-store at browser and CDNs, varies by cookie/authorization, and returns `paidLive,promoLive,promoAvailable,publicOfferLive,reason,expiresAt,remainingToday,checkedAt,validUntil,message`. Public acquisition copy is possible before the signup cutoff only with valid switches/launch and capacity. Generic copy conservatively requires room for 60 seconds plus the maximum allowed fal extras (US$19.42), rather than a partially funded video. User admission still reserves the exact server bound. The lease is at most 15 seconds and ends at UTC midnight, individual expiry or the paid period boundary. A display read is never a reservation; another request can consume the last capacity before generation.

**TESTADO LOCALMENTE — 29/10/2026:** `node --test tests/kling4Promo.test.cjs` passes nine test groups covering switches, malformed launch, exact dates/cutoff, paid-only Stripe/PayPal/Dodo verification, display leases, replays, proof, server-derived identity and browser event protection. `node tests/kling4PromoBudget.cjs <installed-pglite-path>` verifies the actual migration SQL offline: shared global cap including extras, three/day across films and ads, no duplicate allocation, UTC rollover, immutable enrollment, cutoff, event rollback and service-only permissions. Embedded Postgres serializes its requests; this does not prove independent concurrent production connections. Full `tsc --noEmit --incremental false --pretty false` and `git diff --check` pass.

**QUESTÃO PENDENTE / DESCONHECIDO:** no migration was applied, no production credentials/environment file was read, no paid render was run and no deployment was performed. Launch time, opt-in environment values, real billing verification, concurrent production reservation, honest fallback and end-to-end acceptance/delivery remain canary checks for Claude.

**O que está errado ou pode melhorar — SUGESTÃO:** reservation bounds must cover every fal call before it happens. An unbounded still retry, paid fallback or fallback TTS would break the financial premise even if this SQL cap is correct. Keep those paths bounded or disable them for promotion use; verify with provider call traces in the authorized canary.
