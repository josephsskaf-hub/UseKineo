# Como preparar e executar a leitura
**IMPLEMENTADO / OFFLINE.** O preparador não usa credencial, rede nem cliente de banco. Carrega a régua canônica de métricas (lista larga, não contaDaCasaExata), deriva filtros equivalentes sem imprimir endereços e grava SQL somente SELECT num arquivo privado novo em C:/kineo-wt. Recusa sobrescrita, parâmetro de data inválido, tipo desconhecido e escrita SQL.
1. Na branch entregue com node_modules por junção, preparar: node scripts/citacoes-medida-tarde-2411.mjs --kind weekly --cut 2026-11-30T12:00:00Z --out C:/kineo-wt/citacoes-tarde-2411-provas/SEMANAL-3011-EXECUTAR.sql
2. Executar esse SELECT pelo conector autorizado de Supabase no projeto canônico, salvando só agregados, corte e data da leitura. O comando acima prepara a semana 23–30/11 BRT; não executa a consulta.
3. Para a caixa: --kind experiment --cut ISO_OBSERVADO e, após exposição comprovada, --live-from ISO_DA_ATIVACAO. Sem live_from, apenas baseline e depois não observado. Para repetir a janela de 30 dias, --kind thirty --cut ISO_DO_CORTE.
4. Datas em ISO com fuso explícito. Preservar microssegundos recebidos do banco. Copiar só a tabela agregada para a pauta; filtros privados e SQL preparado não vão ao Git nem ao relatório público. Os templates versionados usam :internal_profile_ids para manter a lista fora do Git.
**TESTADO LOCALMENTE.** test-citacoes-medida-tarde-2411.mjs executa o preparador com dados sintéticos: três tipos, exclusão sem endereços crus, datas, proibição de escrita e normalização de caminhos. As provas PostgreSQL são recibos SELECT separados; o teste offline não finge reexecutá-las no banco.
**REPRODUZÍVEL MANUALMENTE.** Nenhum job, credencial, acesso novo ou agendamento foi criado. O vínculo operacional com a pauta de segunda fica no quadro; a rotina de busca existente foi preservada.
